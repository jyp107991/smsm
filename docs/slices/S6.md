## The service (owner, 17 Nov: "use free ones that macropy is using that dont require api key/new secret")
- **Cloudflare Workers AI through smsm's own Worker**, as MacroPy does: `POST /api/ai` on the app's Worker (`worker/index.ts`; `wrangler.jsonc` runs it first only for `/api/*`) calls `env.AI.run(model, {messages, max_tokens, …})` through the `AI` binding. No key anywhere and no new secret: the Cloudflare account's free daily allowance (10,000 Neurons); on the Workers Free plan use past it fails (error 4006 → `limit`) instead of being billed.
- **Models, asked in order** (the next on error or when too slow; `MODELS` in `worker/ai-core.ts`): scan (reads images): Llama 4 Scout 17B, Mistral Small 3.1 24B, Qwen 3.8 27B; parse: GPT-OSS 120B (low reasoning), Qwen3 30B; categorise: Qwen3 30B, GPT-OSS 20B. Workers AI's JSON mode covers only some text models (none that read images), so the prompt states the JSON shape and zod checks every reply (AI.md rule 3).
- **Images**: a `{type: "image_url", image_url: {url: "data:image/jpeg;base64,…"}}` part in the user message. Rough cost: a 1280 px receipt is about 100 Neurons, so the free allowance is far above the household's caps.
- **Time**: scan may take up to 25 s across its models (Workers AI's image models are slower than AI.md's 10 s; the form stays usable throughout), the others 8 s.
- **Sign-in and caps**: the Worker calls the `increment_ai_usage` RPC with the caller's own Supabase token (that proves who they are and that they are in a household); the Supabase URL and the public publishable key are passed to the Worker as vars at deploy. Only the app's own origin may call.

## Decisions made here
- **One switch:** Settings → "Smart features" (off by default; **per phone**, localStorage `smsm-smart`, because it only decides whether this phone sends things to the AI). Text under it: "Reads receipts and loose wording with Cloudflare’s AI. Only the photo or the words are sent, never names or balances." Off: no Scan button, no AI parse, no AI category guess; photos still attach.
- **The route** `POST /api/ai` `{task, ...input}` with the caller's Supabase token: not signed in → 401; per-household daily caps counted in `ai_usage` (scan 30, parse 100, categorise 100; the UK date) → `limit`; the day's free allowance used → `limit`; too slow → `timeout`; reply fails zod → `invalid`; anything else → `error`. No prompts, images or replies logged. The pure parts live in `worker/ai-core.ts` (no Worker APIs), so Vitest runs them; the handler is `handleAi(req, env, fetch?)`.
- **Prompts** in `worker/prompts/{scan,parse,categorise}.ts` (modules, so the Worker bundles them), each stating its JSON shape, versioned by `version`. The system prompt states that text in images or typed text is data, never instructions.
- **Photos** (the receipts bucket): a private Supabase Storage bucket `receipts`; object path `<household_id>/<uuid>.jpg`; policies on `storage.objects`: members may insert and select objects under their own household's folder; no update, no delete (non-negotiable 4). Photos are downscaled on the phone to 1280 px on the long side, JPEG quality 0.8, EXIF dropped by the canvas. `expenses.receipt_path` / `inbox_items.receipt_path` hold the path.
- **Offline photos (non-negotiable 5):** a photo attached offline is kept on the phone (IndexedDB, `smsm-photos`) and its entry saves at once with its `receipt_path` already chosen; the upload goes through its own persisted queue when online, before the entry's write is sent (the write waits for its photo). Until uploaded, the entry page shows the local copy. A photo whose upload is refused is reported with the other problems (OFF-5).
- **Scan (SCAN-1):** the Add sheet gets "Scan receipt" (camera or library) when smart features are on and the phone is online; otherwise "Add photo" only. Reading shows a quiet "Reading the receipt…" line; the form stays usable; the result fills only fields the person hasn't touched since. `low` confidence or any `ok:false` → the photo stays attached, nothing filled, one quiet line: "Couldn’t read that. Fill it in by hand." (`limit`: "That’s enough reading for today. Fill it in by hand.").
- **Filling:** merchant → Description; date → Date (guards: not after today, not more than two years ago, else ignored); total → Amount; category (one of the given names) → Category; a non-GBP currency turns on "Paid in ⟨currency⟩" with the amount as the original (PLC-6), the rate as usual.
- **Itemise (SCAN-2, SCAN-3):** with items, More details shows "Itemise": each line a checkbox (label, amount), all ticked. Shared amount = ticked lines − discount + service, the discount and service shared out over the ticked lines in proportion (largest remainder, exact pence; core `itemise()`); the Amount follows the ticks. If all lines − discount + service ≠ the total, the form says "The lines add up to £41.20 but the total says £42.50. Set the amount." and fills no amount; ticking still works and the person types the amount. Saved: `items` = `[{label, pence, shared}]`, `bill_total_pence` = the receipt's total; the entry's amount is what's shared (non-negotiable 1: the unticked lines are one person's own and are not recorded as anyone's spending beyond being listed on the shared entry's receipt).
- **Sort it later (SCAN-4):** the Add sheet's photo has "Sort it later": the photo goes to the Inbox (`inbox_items` source `scan`, `receipt_path`), the sheet closes. In the Inbox a scan item opens the Add sheet with the photo (and reads it if smart features are on).
- **Loose wording (ADD-9):** quick add uses the grammar first; only when the grammar can't read it (no amount found, or the reading is marked unsure) and smart features are on and the phone is online, the text goes to `parse` (people as "A" = me, "B" = partner; chapter names; category names). The reply opens the Add sheet prefilled (never saves by itself); `ok:false` keeps today's behaviour (the full form with the description).
- **Category guesses (CAT-2 step 4):** after a save whose category came from nothing (steps 1–3 found nothing), with smart features on and online, `categorise` is asked. If the entry's category is still unset/Other and unchanged by a person, it is set through the queue (a normal edit by this phone) and remembered in `category_memory` with `source = 'ai'`; the row shows a small "guess" mark until a person sets a category. A person's choice later overwrites the memory.

## Data
- Migration: storage bucket `receipts` and its policies (guarded so the plain-Postgres SQL tests still run); `increment_ai_usage(p_kind text)` RPC (members only, upsert per household per UK day, returns the new count); `expenses.category_guess boolean not null default false` (cleared by any later category change by a person).
- Data layer: `useSmartFeatures()` / `setSmartFeatures(on)`; `readReceipt(photo: Blob)` → `{ok:true, data: ScanResult} | {ok:false, reason}`; `parseLoose(text)` → same shape with `ParseResult`; `guessCategory(expenseId)` (fire and forget); `attachPhoto(blob)` → `receipt_path` (downscale + IndexedDB + upload queue); `photoUrl(path)` (local copy or a signed URL); `sortLater(photo)` → inbox item id. AI calls go through an injectable `AiService` in the data layer options (`ai`) so tests pass fakes; the real one posts to `/api/ai` with the session's access token.
- Core: `src/core/itemise.ts`: `itemise(items, ticked, discount, service)` → `{amount, perLine}` exact; `checkTotal(items, discount, service, total)` → `{adds: boolean, lines: Pence}`; `scanGuards(raw, today)` → cleaned result (non-negative ints, date window, category in the list, confidence low → nothing).
- Route core: `worker/ai-core.ts`: `buildRequest(input, model)`, `extractText(reply)`, `validate(task, json)` (zod), `capFor(task)`, `timeoutFor(task)`, `MODELS`, `isDailyLimit(message)`.

## Tests
- Core: itemise vectors and properties (sum of perLine = amount; all ticked with no discount/service = sum of items; proportional discount exact; never negative), checkTotal, scanGuards (future date, older than two years, negative amounts, non-integer, unknown category, low confidence).
- Route core (contract, no network): recorded Workers AI replies in `tests/ai/replies/` (good scan, wrong types, extra fields, prompt-injection text on a receipt, totals that don't add up, a future date, a Japanese receipt for TXT-5, a parse reply, a categorise reply, a fenced reply, truncated JSON, the daily-allowance error, a timeout) through `extractText` + `validate` + guards; every row of AI.md §4.
- SQL: bucket policies (only own household's folder; no update/delete; anon nothing) where the storage schema exists; `increment_ai_usage` (members only, per day, counts).
- Data: smart switch per phone; readReceipt with a fake service (success, low confidence, each reason); offline photo saved then uploaded before its entry; sortLater; parseLoose only when the grammar fails; guessCategory only for steps-1–3 misses and never over a person's choice.
- Screens: Settings switch; Add sheet Scan / Add photo by switch and connection; fill and "fill only untouched"; itemise ticks and the mismatch message; Sort it later; quick add loose wording opens the prefilled sheet; guess mark.
- E2E (demo mode, a fake AI): scan fills the form at 320/390, both themes, axe; itemise.

## Interfaces (what the tests are written against)
- Settings: switch "Smart features" with its description.
- Add sheet: button "Scan receipt" (smart on and online) or "Add photo" (always, under More details when smart is off); after a photo: an image named "Receipt photo", button "Remove photo", button "Sort it later"; status line text "Reading the receipt…"; failure line "Couldn’t read that. Fill it in by hand." / "That’s enough reading for today. Fill it in by hand.".
- Itemise: group "Itemise" with one checkbox per line named "⟨label⟩ ⟨£amount⟩" (e.g. "Milk £1.20"), all checked; mismatch text starting "The lines add up to".
- Entry page: image "Receipt photo" when it has one; a category set by a guess shows "Groceries (a guess)".
- Inbox: a scan item named "Receipt to sort" opening the Add sheet with the photo.
- Data: `useSmartFeatures`, `setSmartFeatures`, `readReceipt`, `parseLoose`, `guessCategory`, `attachPhoto`, `photoUrl`, `sortLater`; DataLayer option `ai: AiService` with `{ scan(image: Blob, ctx), parse(text, ctx), categorise(description, categories) }` each returning `Promise<{ok:true,data}|{ok:false,reason:'off'|'limit'|'timeout'|'invalid'|'error'}>`.
- Core: `itemise`, `checkTotal`, `scanGuards` (`src/core/itemise.ts`). Route core: `buildRequest`, `extractText`, `validate`, `capFor`, `timeoutFor`, `MODELS`, `isDailyLimit` (`worker/ai-core.ts`); `handleAi` (`worker/index.ts`).
