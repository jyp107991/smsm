# S10: personal regular payments

Brief per `docs/ENGINEERING.md` §5.1. Source: the owner, 25 Nov 2026 ("should be able to add recurring payments that are not shared, which clearly are separately recorded and filterable as separate individual recurringpayments/bills/subs"; "both of you can see them"; "kept fully separate"; "insights must include and be separately produced for each individual"), recorded as D19; the coordinator's decisions are in `docs/DECISIONS.md` (25 Nov, "S10 …").

## Criteria in scope
- **REC-9** own regular payments: "Whose is it?" (Shared · Mine); both see them; only the owner writes them; marked and filterable apart (Activity's Whose filter, export's "Whose", backup and restore).
- **REC-10** what an own payment posts is an own entry; Bills' "Jae's own" / "Sam's own" with a month and a year and their own subscriptions.
- **REC-11** a change of whose applies from the next payment on; only you make one yours, only its owner makes it shared again (no approval, a history line), never handed over.
- **REC-12** never in a shared figure (balance, settle-up, statement, Insights, recap, pace, notes, What home costs, the calendar and Subscriptions, Ask, Activity's shared total, notifications).
- **INS-10** Insights produces each person's own apart.
- Touched, and re-tested: BAL-1 (the parity of core and `member_net`), EXP-1 (the CSV's new column).

## Out
- An own payment whose amount varies (its bill would sit in the shared Inbox, which both decide on): refused, and noted in `OPEN_ITEMS.md` under Ideas.
- Own one-off entries (typed or imported): not asked for; an own entry exists only as an own regular payment's posting.
- Any budget, income or other personal figure (D1 stands otherwise).

## Data
Migration `20261125000000_personal_regular_payments.sql` (expand only): `recurring.owner_id`, `expenses.owner_id`; `check_personal` (shape; an entry's owner never changes); row-level security for owner-only writes; `recurring_guard` (who may change whose; what is due posts first); `recurring_post_due_one` (owner on posted entries; no "bill posted" for them); `member_net`, `member_net_on`; `notify_expense`, `queue_daily_notifications`, `check_refund_limit`, `check_comment_entry`, `restore_backup`.

## Screens
The regular payment sheet; Bills; Activity (row tag, Whose filter, totals); an entry's page (read-only for the partner, no comments, no Duplicate or Refund); Insights (own sections).

## Risks
- A shared figure counting an own row: covered twice (hooks return shared rows only; the core skips owner rows) and proved by property tests and the SQL parity test with own rows shaped to move the balance.
- Name clashes in tests and for screen readers ("Subscriptions", "Paused or ended"): own lists are unnamed inside their named region.
- Demo data: four own payments added last (fixed amounts), so shared demo figures don't move.
