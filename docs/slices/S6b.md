# S6b: smart features — recap wording, Ask smsm, from outside the app

Brief per `docs/ENGINEERING.md` §5.1; the second half of S6 (S6a is `S6.md`). Same service as S6a: Cloudflare Workers AI through the app's own Worker (`POST /api/ai`), no key. Every rule in `docs/AI.md` applies. Released by default.

## Criteria in scope
INS-2 (the AI wording of the recap; the template stays the fallback), INS-9 (Ask smsm), ADD-8 (app-icon shortcuts and the share sheet), NOT-3's shortcuts and share target (its icon badge waits for S8), AI.md §5 live eval (the tooling; the run needs the owner, below).

## Decisions made here
- **Recap wording (INS-2, AI.md §3.4).** New task `recap` on `/api/ai`: input the month's figures as the core computes them (`recapStats(recap)`: period, total, everyday, usual, comparison, the bar's names and totals, the notes' texts, who paid as A/B), people only as "A"/"B". Output `{ headline: string ≤ 140, aside: string | null ≤ 140 }`, plain and warm, no advice, no judgement about either person. **Guard (core `wordingGuard(stats, reply)`)**: every number in the reply (amounts with or without £ and commas, percentages, counts) must appear in the stats after normalising pounds formatting; "A"/"B" are replaced by the names on the phone; anything else → the template. Once per household per month: the first phone to open a finished month's recap asks; the reply is stored with `save_recap_prose(period, stats, prose)` (an RPC, members only, never overwrites) in `recaps`; the other phone reads it. Smart features off, offline or any failure: the template headline, as in S5b. The so-far recap (settle day) is never worded by the AI (it changes daily).
- **Ask smsm (INS-9, AI.md §3.5).** Insights gets a box "Ask smsm" (smart features on and online; otherwise not shown) with a "Ask" button. The question goes to task `ask` with the category names, chapter names, countries present, today. The reply is the closed schema of AI.md §3.5 (`measure`, `filters`, `group_by`) or `{ unsupported: true }`. The phone validates it, maps names to ids (unknown names dropped), and runs it with the same filter code as Activity (`src/core/filters.ts`) and the same money rules as Insights (`sharedSpend` etc.): **code computes the figure, never the AI**. The answer area shows: the figure as a sentence ("£612.40 on Eating out in Japan, all time"), the filter as removable chips ("Eating out", "Japan", "All time") — removing one re-runs it at once — and the matching entries (rows, newest first, up to 50 with "See all in Activity"). `unsupported` or any failure: "I can answer totals, counts, averages and the biggest, by category, chapter, country, who paid and dates." Cap: ask 50 per household per day.
- **Shortcuts (ADD-8).** The web app manifest gets `shortcuts`: "Add expense" (`/?do=add`), "Scan receipt" (`/?do=scan`), "Settle up" (`/?do=settle`). Opening with `?do=…` opens that sheet on Home once (the parameter is removed from the address). "Scan receipt" opens the Add sheet and its camera button (or "Add photo" when smart features are off).
- **Share target (ADD-8, SPEC 5.3).** The manifest gets `share_target` (`/share`, POST, multipart, `image/*` file and `text`/`title`/`url`). The service worker handles `POST /share`: it keeps the shared image in the phone's photo store (IndexedDB `smsm-photos`, under `shared/<uuid>`) and the text in `smsm-shared`, then redirects to `/?do=shared`. The app opens the Add sheet with the photo (read if smart features are on and online, exactly like Scan receipt) or, for text, with the text in Description (quick add's grammar first; ADD-9 loose wording if smart features are on). Offline, a shared photo opens the sheet with the photo attached (Sort it later works). Nothing is sent anywhere by sharing alone.
- **Live eval (AI.md §5).** `npm run eval:ai` runs the receipts, parse phrases and ask questions in `tests/ai/eval/` against Workers AI using the Cloudflare REST API (`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; the same models and prompts as the Worker, through `worker/ai-core.ts`), and prints the pass marks; a manual GitHub workflow `eval-ai` runs it with the repository's existing secrets and writes the result to the job summary. 20 receipts are generated by a script (rendered UK receipts: supermarket, restaurant with service, pharmacy, a long one, a low-light one, a euro one, a yen one). **The owner's real receipt photos never go in this public repository** (see Owner below).

## Data
- Migration: `save_recap_prose(p_period text, p_stats jsonb, p_prose text)` (security definer, members only, period `YYYY-MM` before this month, insert-only: an existing row is returned unchanged); `increment_ai_usage` accepts `recap` and `ask` (already does).
- Worker: tasks `recap` and `ask` in `worker/ai-core.ts` (`MODELS.recap`, `MODELS.ask`, caps recap 3/day and ask 50/day, timeouts 8 s), prompts `worker/prompts/{recap,ask}.md` + schemas. Reply schemas in `src/core/aiReplies.ts`.
- Core: `src/core/wording.ts`: `recapStats(recap, people)` and `wordingGuard(stats, reply, names)` → `{ headline, aside } | null`. `src/core/ask.ts`: `askFilter(reply, lookups)` → a filter for `src/core/filters.ts` plus `measure`/`group_by`, and `answer(entries, filter, measure, groupBy, today)` → `{ figure: Pence | number, sentence, groups? }`.
- Data: `recapWording(month)` → `{ headline, aside } | null` (stored prose, else asks once, else null); `askSmsm(question)` → `{ ok: true, data: AskReply } | { ok: false, reason }`; `takeShared()` → `{ photo?: Blob, text?: string } | null` (reads and clears what the service worker kept).
- PWA: manifest `shortcuts` and `share_target`; service worker custom code via vite-plugin-pwa `injectManifest` or `importScripts` (builder's choice; documented).

## Tests
- Core: wordingGuard (numbers in the stats pass; any other number, a changed amount, a percentage not in the stats, an advice word list → null; A/B replaced), recapStats (A/B only, no names), askFilter (closed schema; unknown names dropped; dates), answer (total/count/average/largest; group_by; equals Insights' sharedSpend for the same filter; money back subtracts).
- Worker: recap and ask requests (least data), replies validated, caps.
- SQL: save_recap_prose (members only, once, period rules), recaps read by members.
- Data: recapWording (stored first; asks once; failure → null; off/offline → null without asking), askSmsm (off/offline → off; reasons pass through; invalid → invalid), takeShared.
- Screens: recap headline from the AI when stored and guarded, template otherwise; "Ask smsm" box (shown only with smart on and online), the answer sentence, chips (remove one re-runs), rows, the unsupported line; `?do=add|scan|settle` opens the sheet once; `?do=shared` with a photo or text.
- E2E: Ask smsm and a recap at 320/390, both themes, axe; the manifest has the shortcuts and share target.

## Interfaces (what the tests are written against)
- Insights: region "Ask smsm" with textbox "Ask smsm" and button "Ask"; the answer: a status line with the sentence; a list "Filters" of buttons named "Remove ⟨chip⟩"; a list "Matching entries"; the unsupported line text starting "I can answer".
- Recap: region "Headline" holds the AI headline (and aside, if any) when present and guarded, else the template sentence.
- URL: `/?do=add` → dialog "Add expense"; `/?do=scan` → dialog "Add expense" with its file input opened (or "Add photo" when smart is off); `/?do=settle` → dialog "Settle up"; `/?do=shared` → dialog "Add expense" with image "Receipt photo" (a shared photo) or Description set (shared text).
- Data: `recapWording`, `askSmsm`, `takeShared`; `AiService` gains `recap(stats)` and `ask(question, ctx)`.
- Core: `recapStats`, `wordingGuard` (`src/core/wording.ts`); `askFilter`, `answer` (`src/core/ask.ts`).
