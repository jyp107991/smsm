# S4a: chapters

Brief per `docs/ENGINEERING.md` §5.1. Status: started 17 Nov, after S3 went live. S4 in `BUILD_PLAN.md` is split into two releases so each lands sooner (owner: small, frequent releases): **S4a chapters** (this brief) and **S4b places and other currencies** (PLC-1…PLC-7, CHP-6; a brief of its own). Process: money, saving and syncing take the full protocol (tests first by a separate agent, fresh review); screens and wording take the owner's lighter process.

## Goal
A trip or a project keeps its own total without a second ledger: entries can belong to a chapter, a chapter page shows what it cost and who paid, and while a chapter is current new entries go into it. There is still one balance.

## Criteria in scope
CHP-1 (create from Settings → Chapters and from the Add form; the trip suggestion is S4b; a trip's country is chosen from a list), CHP-2, CHP-3 (places and photos wait for S4b and S6: the page shows them once they exist), CHP-4. CHP-5 is about Insights (S5): S4a provides `everydayOnly` in the core for it and nothing else. ACT-1's filters gain "Chapter".

## Out of scope
Country on entries, place capture, location, trip suggestions, "welcome home", other currencies (S4b). Insights (S5). Photos (S6).

## Decisions made here (recorded in DECISIONS)
- **"Current chapter" is per phone** (like the current country, PLC-3), kept in localStorage `smsm-current-chapter`. Each person sets it on their own phone; it never changes the other phone. A closed chapter is never current.
- A chapter's **total** = its expenses minus its money back (not deleted). **Days** = start to end inclusive when both are set; otherwise first to last entry date (start or end filling in when set; an open trip with a start runs to today). **Per day** (trips only) = total ÷ days, rounded once to the penny, halves up.
- **Who paid** = the sum of each person's `paid` over the chapter's expenses minus money back they received. **By category** = the same per category, largest first.
- Chapters are **closed, never deleted** (revoke delete; `closed` true/false; Reopen brings one back). Edits are logged (`log_activity` for `chapters`, entity `chapter`). Realtime streams `chapters`.
- Recurring posts and Inbox keeps are never in a chapter (REC-4, already enforced).

## Screens
- **Settings → "Chapters"** (a link like Categories) → page h1 "Chapters": open chapters as notebook cards (walnut spine, emoji, name, dates, total), then "Closed"; button "Start a chapter".
- **Chapter sheet** ("New chapter" / "Edit chapter"): Name, Emoji, Kind (Trip / Project), Starts and Ends (optional, the app's calendar), Country (trips only, a list of countries by name; default the home country).
- **Chapter page** (`/chapter/:id`): h1 the name with its emoji; one sentence ("£1,840.00 over 9 days, £204.44 a day" for a trip; "£3,200.00 so far" for a project); "By category"; "Who paid"; its entries (the usual rows); buttons "Add to this chapter" (makes it current), "Stop adding to it" (when current), "Edit", "Close chapter" / "Reopen".
- **Add sheet**: when any chapter is open, a "Chapter" group in the main form: "Everyday" and each open chapter as chips; the current chapter is chosen by default for a new entry; editing keeps the entry's own chapter.
- **Home**: when this phone has a current chapter, a chip beside quick add: "Adding to Japan 🗾" (tapping opens the chapter page). Quick add puts entries into the current chapter too.
- **Activity**: a "Chapter" filter (Everyday or a chapter). **Entry page**: the chapter's name, linking to its page.

## Data
- `chapters` exists (baseline). New migration: `revoke delete`, `log_activity` trigger for chapters, realtime publication. SQL tests extend `tests/sql/`.
- Data layer: `useChapters()` (all, overlaying waiting writes), `saveChapter(draft & {id?})`, `closeChapter(id, closed = true)`; through the persisted queue (`MoneyOp` table `chapters`, upsert by phone-made id); memory Api `chapters` table + `upsertChapter`. `addExpense` / `editExpense` / quick add carry `chapterId`.
- Core (`src/core/chapters.ts`, pure, property-tested): `chapterSummary(chapter, entries, people, today)` → `{ total, days, perDay | null, byCategory[], byPerson }`; `everydayOnly(entries)` for S5.
- No new packages. Country names from `Intl.DisplayNames`.

## Tests
- SQL: no delete; edits logged; published to realtime; an entry may point only at its own household's chapter (RLS on the referenced row is already there: check).
- Core: summary vectors (trip with dates, project without, money back, deleted entries ignored, per-day rounding) and properties (total = sum over categories = sum over people).
- Data: save/close through the queue offline; overlay; entries carry chapter_id.
- Screens (`src/screens/chapters.test.tsx`) and e2e (`tests/e2e/chapters.spec.ts`, 320/390 px, both themes, axe).

## Risks
- Per-phone "current" could surprise the partner: the chip on Home and the Add form make it visible.
- Days for open-ended chapters: stated above.

- Chapter page: region "Summary" containing the sentence: trip with dates "£1,840.00 over 9 days, £204.44 a day"; project "£3,200.00 so far"; a closed project "£3,200.00 in all". Region "By category" (list items "Groceries £120.00"), region "Who paid" (list items "Jae £100.00"), list "Entries". - Activity: filter button "Chapter"; its picker offers "Everyday" and each chapter by name.
- Entry page: a link with the chapter's name.
- Data: `useChapters`, `saveChapter({ name, emoji, kind, country, startDate, endDate, id? })` → id, `closeChapter(id, closed?)` → boolean; `ExpenseDraft.chapterId?: string | null`; `setCurrentChapter(id | null)` / `useCurrentChapter()` in `src/data` (localStorage, per phone).
