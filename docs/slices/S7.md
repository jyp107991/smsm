# S7: import and export

Brief per `docs/ENGINEERING.md` §5.1. Released by default (owner, 17 Nov). No Splitwise (DECISIONS 17 Nov).

## Criteria in scope
IMP-1 (CSV import: Monzo preset and generic column mapping, read on the phone), IMP-3 (one card at a time in the Inbox: Keep / Not ours, "always do this for …", hashed ignores, never imported twice), EXP-1 (CSV of entries and settle-ups for any range; a monthly PDF statement; restoring the full JSON backup), EXP-3 (storage used against the free plan, warning at 80%), INB-1's "import rows being reviewed", OFF-3's "reading a CSV for import, and CSV, PDF and JSON export" offline.

## Decisions made here
- **Monzo preset (IMP-1).** Monzo's CSV export (personal account), checked 18 Nov 2026 from third-party converters because Monzo publishes no column list: `Transaction ID, Date, Time, Type, Name, Emoji, Category, Amount, Currency, Local amount, Local currency, Notes and #tags, Address, Receipt, Description, Category split, Money Out, Money In` (a business export adds `Balance, Balance currency`). Date `dd/mm/yyyy`, time `HH:MM:SS`. `Amount` is signed in the account's currency (spending negative); `Local amount`/`Local currency` is what the merchant charged. The preset is chosen when the header has `Transaction ID`, `Date`, `Name` and `Amount` (any order, any case, extra columns ignored). Bank id = `Transaction ID`; description = `Name` (else `Description`); amount = −`Amount`; category hint = `Category`; when `Local currency` isn't GBP the note reads "Paid €89.99" (from `Local amount`, as typed). Rows with `Type` "Pot transfer" are left out. ★ The owner's real file confirms it when they have one; a header that doesn't match falls back to the mapping step, so nothing breaks.
- **Generic CSV (IMP-1).** Mapping step: pick the columns for Date, Description, and either one Amount column (with "Spending is shown as: negative / positive") or Money out + Money in; optionally a Bank id column. Date format: `dd/mm/yyyy` (default), `yyyy-mm-dd`, `mm/dd/yyyy`; `d/m/yy` forms accepted for the chosen order. Without a bank id column the row's id is made from date, amount, description and its position among identical rows in the file (`gen:` + hash), so the same file imported again matches itself.
- **Only spending (IMP-1).** Rows that are money out are offered; money in, zero, unreadable dates or amounts are left out and counted ("12 payments in and 1 unreadable row left out"). Refunds stay a person's Money back.
- **Reading (IMP-1).** RFC 4180 CSV on the phone: a BOM, CRLF or LF, quoted fields with commas, quotes and newlines; at most 5 MB and 20,000 rows ("That file is too big. Export a shorter period."). Amounts are read into pence by `parseAmount`'s rules (commas as thousands, "£" and spaces ignored, more than 2 decimals refused). Nothing leaves the phone while reading.
- **Where rows wait (IMP-3, INB-1).** Rows being reviewed live **only on the importing phone** (IndexedDB `smsm-import`), never in the database: "discarded rows are never stored". The Inbox shows them after its own items, one card at a time, in date order, under the same counter. The other phone never sees them.
- **What is already decided (IMP-3).** Before cards are made, a row is dropped when (a) its id hash is in `import_ignores`, (b) an entry already has `source` and `external_id` equal to it (deleted entries count), or (c) it is already waiting on this phone. The hash is `sha256(household_id + ":" + source + ":" + bank id)`, lower-case hex, computed with Web Crypto (works offline). `source` is `monzo` for the preset and `csv` for a mapped file.
- **The card (IMP-3).** Shows description, amount, date, "Paid by ⟨importer⟩", and a category (rule, else learned memory, else the Monzo category when it equals a category's name, ignoring case, else none). Buttons: **Keep** (adds the entry at once with those values and the household's default split; `source`, `external_id` set; toast with Undo), **Change first** (opens the Add sheet prefilled; saving keeps it), **Not ours** (writes the hash to `import_ignores`; the row is forgotten; toast with Undo, which removes the hash). A tick box "Always do this for ⟨description⟩" makes the choice a rule (`import_rules`: match on the normalised description, `src/core/text.ts`; keep with the category and split used, or skip). Below the card: "Stop reviewing" forgets the remaining rows on this phone without recording anything (they'll be offered again next time).
- **Rules (IMP-3).** On the next import, rows matching a **skip** rule are ignored (hash written) and rows matching a **keep** rule are kept with the rule's category and split, payer the importer, when the person taps "Import N rows"; the summary before that tap says so ("Your rules will keep 4 and skip 2"). Settings → "Import rules" lists them with Remove.
- **Payer.** The importer: it's their statement. Change first lets them pick the other person (a joint account's statement). Split: the household default.
- **Queue.** Ignores, ignore removals and rules are written through the same persisted queue as money (offline safe; retried). A keep that hits the `expenses_external` unique index (the other phone imported the same row first) is dropped quietly, not shown as a problem.
- **CSV export (EXP-1).** Settings → Export → "Entries as CSV": a From and To date (default this month), then a file `smsm-entries-YYYY-MM-DD-to-YYYY-MM-DD.csv` built on the phone (offline too): `Date, Type (Expense | Money back | Settle-up), Description, Category, Chapter, Country, Amount, Paid by, ⟨Name A⟩'s share, ⟨Name B⟩'s share, Notes, Deleted (yes/blank)`; amounts as plain pounds `42.50`; UTF-8 with BOM, CRLF; a cell starting `=`, `+`, `-`, `@`, tab or CR is prefixed with `'` (spreadsheet formula injection). Deleted entries are included and marked.
- **PDF statement (EXP-1).** Settings → Export → "Monthly statement": pick a finished or current month; opens `/statement/YYYY-MM`, a print-ready page, and the phone's print sheet ("Save as PDF"). No PDF library: the browser makes the PDF (offline, the app's own fonts, nothing new to load). Content: household names, month, balance at the start (all settled activity before the month) and at the end, every entry and settle-up of the month (date, description, amount, paid by, each share), totals paid and shared by each person, the generated date. Print stylesheet: light theme, no navigation, page breaks between rows avoided. Figures from the core (`netPositions`) — the end balance equals the app's balance for that date.
- **Restore (EXP-1).** Settings → "Restore from a backup": pick an `smsm-backup-*.json`, see a summary ("Adds 1,204 entries, 31 settle-ups, 3 chapters. Nothing already here changes."), map the backup's two people to this household's two (by name; a "Swap" button), then Restore. **It only adds**: rows whose id is already in this household are left alone; nothing is changed or deleted. Regular payments come back paused ("turn them on in Bills"), so nothing posts on its own. Both people must have joined. Online only ("Restoring needs a connection"). Sent in chunks of at most 500 rows to `restore_backup(p_people jsonb, p_rows jsonb)`; safe to repeat. Deleted entries come back deleted (history). Every restored row is logged by the database as usual.
- **Backup format 2.** The JSON backup gains `chapters`, `recurring`, `comments` and `import_rules` (`format: "smsm-backup-2"`). Restore reads 1 and 2.
- **Storage used (EXP-3).** Settings shows "Storage: 12 MB of 500 MB database, 40 MB of 1 GB photos" from an RPC `storage_used()` (database size and the household's receipt bytes), with a warning line at 80% or more ("Nearly full: export and remove old receipt photos, or move to a paid plan"). The free plan's limits are read from Supabase's current pricing page when built and recorded in DECISIONS. Offline: the last figure, with its date.

## Data
- Migration `…_import_export.sql`: `restore_backup(p_people jsonb, p_rows jsonb)` (security definer; caller must be a member; household must have two members; `p_people` maps each backup user id to a member of this household; `p_rows` is `{ categories?, chapters?, expenses?, settlements?, recurring?, comments?, category_memory?, import_rules? }`; ids already in this household skipped; an id found in another household gets a new id (references inside the same call follow it); money rows keep the database's own checks (paid and shares sum to the amount); returns counts added and skipped; ≤ 500 rows a call); `storage_used()` → `{ database_bytes, photo_bytes }` for members. `inbox_items`, `expenses`, `import_ignores`, `import_rules` unchanged (they already hold what this needs). ## Tests
- Core: parseCsv (quotes, embedded commas/quotes/newlines, BOM, CRLF, empty trailing line, ragged rows), detectPreset (the Monzo header in any order and case; business columns; anything else null), readRows (Monzo: signed amounts, pot transfers left out, money in counted, local currency note; generic: each date format, single signed column both ways, out/in columns, generated ids stable across reads and unique among identical rows), exportCsv (columns, plain pounds, formula prefix, BOM/CRLF, deleted marked, range inclusive), statement (closing equals `netPositions` up to the month end; opening plus the month equals closing; shares sum), property tests (export round trip: amounts parse back to the same pence; parseCsv of a csvCell-built row returns the cells).
- SQL: restore_backup (members only; two members required; skips existing ids; never updates or deletes; ids clashing with another household renamed and their references followed; paid/shares checks still refuse a bad row; balance view after restore equals the backup's balance with people mapped; repeat is a no-op; ≤ 500 rows), storage_used (members only), import_ignores and import_rules RLS (own household only).
- Data: idHash vector; startImport drops ignored, already-imported (including deleted) and waiting rows; rules applied; keepImport writes source/external_id and the default split; skipImport writes the hash only (never the row); undo; stopReviewing records nothing; a unique-index refusal on keep is dropped quietly; backup format 2 round trip; restorePlan refuses other files and reports counts.
- Screens: Import (Monzo file → summary → Import; other file → mapping; too big; nothing new), Inbox import cards (Keep, Change first, Not ours, "Always do this for", Stop reviewing, counter with bills first), Export (CSV range download), Statement page (opening, rows, closing, totals), Restore (summary, mapping, swap, offline refusal), Import rules (list, remove), Storage (figures, 80% warning).
- E2E: import a Monzo CSV fixture to cards, Keep one and Not ours one, at 320/390, both themes, axe; the statement page prints (no horizontal overflow; `@media print` hides navigation).
