# S1: the money core

Brief per `docs/ENGINEERING.md` §5.1. Status: in progress (started 2026-11-16, in parallel with S0's look).

## Goal
Pure TypeScript in `src/core/` that every later screen relies on to get money, dates and wording right. No React, no network, no clock: "today" and "now" are arguments. No screens in this slice.

## Criteria in scope (core part; the screens that use them come in S2–S4)
BAL-1, BAL-4 (rule only), SPL-1, SPL-2, SPL-3, SPL-5, ADD-1, ADD-3 (default filling only), ADD-5, MB-3, CAT-2 (steps 1–3), CAT-3, CAT-4, REC-2 (dates), TXT-3, TXT-4, DAT-1, DAT-3, DAT-4.

## Out of scope
Anything that draws or stores; the AI steps (CAT-2 step 4, ADD-9: S6); analytics and recap figures (S5); other-currency and itemise maths (S4, S6); CSV (S7). `paid` stays a map so a joint payer can be added later, but no joint-account input is built (P4).

## Modules and their contracts
All amounts are integer pence with the branded type `Pence`. All dates are `IsoDate` strings `YYYY-MM-DD`. People are `UserId` strings.

### `src/core/money.ts`
```ts
export type Pence = number & { readonly __brand: 'Pence' };
export function pence(n: number): Pence;               // throws unless Number.isSafeInteger(n)
export function sumPence(xs: readonly Pence[]): Pence;
export function parseAmount(text: string): Pence | null;
  // "42.5" → 4250, "£42.50" → 4250, "1,200" → 120000, "12+8.50" → 2050, "18.50+4+12" → 3450,
  // full-width digits "４２．５" → 4250, "0" and negatives and >2 decimals and junk → null.
  // Sums allow + only. Amounts above £1,000,000 → null.
export function formatPence(p: Pence): string;          // 4250 → "£42.50", 120000 → "£1,200.00", -500 → "−£5.00" (U+2212)
```

### `src/core/split.ts`
```ts
export type UserId = string;
export type PenceMap = Readonly<Record<UserId, Pence>>;
export type SplitMode = 'ratio' | 'exact' | 'for_other' | 'treat';
export type SplitParams =
  | { mode: 'ratio'; ratio: Readonly<Record<UserId, number>> }   // whole percentages summing to 100
  | { mode: 'exact'; amounts: PenceMap }                          // must sum to the amount
  | { mode: 'for_other' }
  | { mode: 'treat' };
export function ratioShares(amount: Pence, ratio: Readonly<Record<UserId, number>>, payer: UserId): PenceMap;
  // largest remainder; leftover pennies to the payer first (SPL-3). £42.51 50/50 paid by A → A 2126, B 2125.
export function computeEntry(input: { amount: Pence; payer: UserId; members: readonly [UserId, UserId]; split: SplitParams }):
  { paid: PenceMap; shares: PenceMap };
  // for_other: payer's share 0, other owes all. treat: shares = paid. Every key of both members present (0 allowed).
export function validateEntry(e: { amount: Pence; paid: PenceMap; shares: PenceMap; mode: SplitMode; members: readonly [UserId, UserId] }): string[];
  // [] when valid. Mirrors the database's check_money exactly (sums, non-negative, members only, for_other, treat).
export function resolveDefaultSplit(c: { remembered?: SplitParams | null; categoryDefault?: Readonly<Record<UserId, number>> | null;
  householdDefault?: Readonly<Record<UserId, number>> | null; members: readonly [UserId, UserId] }): SplitParams;   // SPL-2; nothing → 50/50
```

### `src/core/recurring.ts`

export interface Schedule { frequency: 'weekly' | 'monthly' | 'yearly'; every: number; startDate: IsoDate; endDate: IsoDate | null }

### `src/core/categorise.ts`
```ts
export interface CategoryRef { id: string; name: string }
export interface Memory { categoryId: string | null; split: SplitParams | null; source: 'user' | 'ai' | 'seed' }
export type MemoryMap = ReadonlyMap<string, Memory>;                  // key = normaliseKey(description)
export interface Suggestion { categoryId: string | null; split: SplitParams | null; source: 'memory' | 'history' | 'seed' | 'none' }
export function suggest(description: string, ctx: { memory: MemoryMap; history: readonly { description: string; categoryId: string | null }[];
  seed: Readonly<Record<string, string>>; categories: readonly CategoryRef[] }): Suggestion;
  // CAT-2 order: (1) exact memory; (2) close history match (normalised; a history description that starts with, or is contained in, the
  // typed text, longest wins); (3) seed list (content/merchants.json: normalised name → category NAME, mapped to this household's id by name).
  // Never "Other" here: 'none' lets the caller decide. A 'user' memory always beats 'ai'.
export function learn(memory: MemoryMap, description: string, choice: { categoryId: string | null; split: SplitParams | null }): Map<string, Memory>;   // CAT-3, CAT-4
```

### `src/core/quickadd.ts`
```ts
export interface QuickAddContext { today: IsoDate; me: UserId; partner: UserId; names: Readonly<Record<UserId, string>>;
  animals: Readonly<Record<UserId, 'cat' | 'dog'>>; categories: readonly CategoryRef[] }
export interface QuickAddReading {
  amount: Pence; description: string; categoryId: string | null;      // only when a category word or prefix was typed
  payer: UserId; split: SplitParams | null;                            // null = not typed (caller applies defaults, ADD-3)
  date: IsoDate; tags: string[]; confident: boolean;                   // confident=false → caller may use the AI parse (S6)
}
export function parseQuickAdd(text: string, ctx: QuickAddContext): QuickAddReading | null;   // null when no amount
```
Grammar (ADD-1, TXT-4): the amount (required; first token that `parseAmount` reads, anywhere) and then in any order: a category word or a prefix of at least 3 letters matching exactly one category; payer (`me`, either name, `cat`/`dog`; "X paid" too); split (`60/40` = payer/other, `treat`, `for <name>`, `for them`); date (`today`, `yesterday`, weekday names or 3-letter forms = the most recent such day on or before today… but never today itself unless typed `today`, `12/11` = day/month in the current year, or last year if that is in the future, `12/11/25`); `#tag`; remaining words, in their order and original spelling, are the description (any language). Command words are English and case-insensitive. Never throws (property test on arbitrary strings). At least 80 phrases in `tests/vectors/quickadd.json`.

## Data touched
None in the database. `content/merchants.json`: about 250 common UK merchants and words → one of the 12 default category names.

## Tests (written first by a separate agent from this brief and the spec)
- `src/core/*.test.ts`, each test named with the ids it covers.
- Vectors: `tests/vectors/quickadd.json` (≥ 80), `split.json`, `recurring.json`, `balance.json` (includes DATA_MODEL §3's worked example).
- Properties (fast-check): shares and paid sum to the amount and are never negative; nets sum to zero; swapping the two people negates the balance; adding then soft-deleting an entry leaves the balance unchanged; quick-add never throws.
- Fixed moments (DAT-4): 31 Dec 23:59, 29 Feb, both UK clock-change Sundays (Europe/London), and a phone in Tokyo.
- Against PostgreSQL when `PGHOST` is set: recurring dates equal SQL's for 500 random schedules; `netPositions` equals the `member_net` view for random households.
- Mutation: Stryker on `src/core/{money,split,balance,recurring}.ts`, score ≥ 85%.

## New packages
None beyond S0 (fast-check and Stryker are already in).

## Risks
- Quick-add ambiguity (is "tesco 3" an amount?): the first token that reads as an amount wins; vectors pin the behaviour.
- `Intl` time-zone support in Node and old Android WebViews: Node 22 has full ICU; Chrome on Android does too.
