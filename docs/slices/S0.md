# S0: the pipeline and the look

Brief per `docs/ENGINEERING.md` §5.1. Status: in progress (started 2026-11-16).

## Goal
An empty but real, installable app deployed by a pipeline that refuses to ship a broken commit; the database baseline applied through that pipeline; and a deployed gallery where the owner chooses the logo and typeface and confirms the palette by looking.

## Criteria in scope
SPEC ids touched by S0 (each gets a test named with its id):
- **BAL-3** (component level): the plank tilts with a balance, proportionally, capped at 8° (reached at £200), level at zero, toward whoever is owed. The live balance arrives in S2.
- **TXT-6** (partial): the type stacks fall back to system fonts for Hangul; truncation helper uses `Intl.Segmenter` (whole graphemes).
- **TXT-7**: every interface string lives in `src/ui/strings.ts`; a lint/test check finds no literal copy in screens.
- **DAT-5** (partial): every dependency is pinned to an exact version in `package.json` and the lockfile; the AI model id is a setting (enforced in S6).

S0's own checks (no SPEC id; tested by name):
- Pipeline: PR checks, main deploy (migrations → functions → build → Cloudflare → smoke test), preview URL per PR, keep-alive.
- Tokens: every used text/background pair meets WCAG AA in both themes (automated).
- Gallery: renders at 390×800 and 320×568 without horizontal overflow, both themes, axe clean, reduced motion stops all motion.
- Error reporting to `client_errors`; version and build shown; "Updated. Tap to refresh" prompt.
- `npm run trace`: fails on an id with neither a test nor a deferral, and on a test naming an unknown id.

Every other SPEC id is listed in `docs/OPEN_ITEMS.md` → Deferred criteria with the slice it moves to, so `trace` is clean from the first commit.

## Out of scope
Sign-in, any real data on screen (S2); money logic (S1, built in parallel); pushing Auth config to the live project (needs the owner's approval of the diff); sign-in email delivery (owner question); the nightly backup job (S2); notifications (S8).

## Screens touched
- `/` the app shell: logo, "Shared money for two", version. (Sign-in replaces it in S2.)
- `/gallery` (demo build only): logo variants at 48 px; three type options on a realistic Home; palette in both themes including the fifth colour; the plank at five balances; both animals in every mood × pose with motion on and off; an entry row, the add sheet and a recap card with realistic data; category colours.

## Data touched
- `supabase/migrations/20261116000000_baseline.sql`: `supabase/schema.sql` exactly as tested.
- `supabase/migrations/20261116000100_hardening.sql`: (1) functions are no longer executable by `public`/`anon` (PostgreSQL grants EXECUTE to PUBLIC by default; `post_due_recurring(uuid)` skipped its household check when called without a sign-in); (2) `health()` RPC, callable by `anon`, for the smoke test and keep-alive. Tests added to `tests/sql/`.
- `supabase/schema.sql` becomes a generated snapshot (`npm run db:snapshot`), checked for drift in CI.
- `supabase/config.toml`: declares the project id and the Auth settings the app depends on. **Not pushed** until the owner approves; a read-only workflow shows the exact diff.
- `src/data/database.types.ts`: generated from the migrated database, never hand-written.

## Pipeline design
- `ci.yml` (pull requests, pushes to any branch): install → typecheck → lint → unit → trace → SQL (PostgreSQL 16 service) → schema snapshot drift → build → Playwright (gallery, shell) → on PRs, upload the demo build as a preview version of the `smsm-demo` Worker and comment-free summary with the URL.
- `deploy.yml` (push to `main`): reuses the CI checks, then `supabase db push` (migrations only; never `config push`), Edge Functions (none yet: skipped when the folder is empty), production build with `VITE_*` variables, `wrangler deploy` of `smsm` (the app) and `smsm-demo` (demo build with the gallery), smoke test (shell loads, `/version.json` matches the commit, service worker is served, `health()` answers).
- `keepalive.yml`: every 2 days calls `health()` with the publishable key.
- `auth-config.yml` (manual only): runs `supabase config diff` and prints it; pushes only when started with `apply: push` after the owner has approved.

## New packages (all pinned exactly)
react, react-dom (UI); vite, @vitejs/plugin-react (build); typescript 6.0 (typescript-eslint does not yet support 7); tailwindcss + @tailwindcss/vite (styling); vite-plugin-pwa + workbox-window (install, offline, update prompt); @supabase/supabase-js (client); zod (boundaries); motion (springs, used by the plank); vaul (bottom sheet); @radix-ui/react-dialog, @radix-ui/react-tabs, @radix-ui/react-toggle-group (accessible primitives); lucide-react (icons); @fontsource-variable/{bricolage-grotesque,fraunces,figtree,nunito} (the three type options; two are dropped after the owner chooses); vitest, fast-check, @stryker-mutator/core + vitest-runner (tests); @playwright/test + @axe-core/playwright (end-to-end, accessibility); eslint, typescript-eslint, eslint-plugin-react-hooks (lint); supabase (CLI), wrangler (deploy).

## Risks
- A secret or variable is wrong → the first deploy run names which one; the owner is told exactly where to fix it.
- Cloudflare account without a `workers.dev` subdomain → first deploy fails with a clear message; one-time owner step.
- Supabase CLI v3 is new (3.2.0 released today); pinned to 3.2.0, behaviour read from its own `--help`. Its `config push` leaves undeclared settings alone (v2 overwrote them with defaults; `DEPLOY.md` warning updated).
- Fonts: three families add weight; only the chosen one ships after the owner decides.
